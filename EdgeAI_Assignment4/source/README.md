## Local setup and execution

Run `setup_windows.bat` to create `.venv` in this directory and install CUDA PyTorch. NVIDIA drivers are required for GPU training. Everything generated by the runner, including temporary files and caches, stays in this directory.

```powershell
.\.venv\Scripts\python.exe run_assignment.py --quick
.\.venv\Scripts\python.exe run_assignment.py
```

The smoke run has a separate output folder. The full run trains the teacher for 15 epochs, each of six students for 20 epochs, searches 30 NAS candidates for up to four epochs each, and trains the selected CNN from scratch for 30 epochs. Runtime depends on laptop thermals and power. Connect AC power for sustained training.

The runner writes `Assignment4_executed.ipynb` after every completed cell. Models, optimizer/scaler/scheduler state, RNG state, feature adapters and histories are saved atomically after each epoch. Re-running resumes unfinished models and loads finished models. Do not enable `FORCE_RETRAIN` unless you intend to retrain.

Every completed epoch is also retained under `checkpoints/epochs/<model>/`. These local recovery archives use NTFS hard links where available and are excluded from the submission ZIP and GitHub to keep deliverables compact. Expect several additional GB for the full optimizer histories.


Model keys: `mobilenet_v2_baseline`, `mobilenet_v2_kd`, `squeezenet_baseline`, `squeezenet_kd`, `efficientnet_lite0_baseline`, `efficientnet_lite0_kd`, `nas_best`. Notebook inference and `inference.py` use the same resize/normalization order. `onnx/onnx_infer.py` is a minimal ONNX-only deployment alternative.

The ONNX backend of `inference.py` needs only NumPy, Pillow and ONNX Runtime. Its NumPy bilinear interpolation was checked against notebook preprocessing at all three input resolutions. Use `python show_progress.py` to inspect saved training metrics while the notebook runs.

The notebook is the training/search source; `notebook_source.py` is its executable Python equivalent. `models.py` contains the architecture builders. `run_assignment.py` executes training and search; `benchmark.py` repeats CPU timing independently. `finalize_assignment.py` validates completed outputs and generates the report/package without retraining.

## Experimental interpretation

NAS candidate selection uses a held-out subset of CIFAR-10 training data; CIFAR-10 test data is used only to monitor final training and evaluate the final network. CPU search limits are 10 ms median latency, 1 MB ONNX storage, and 200 MiB incremental peak process memory where supported. Timing uses one CPU thread and batch size one. The report explains denominators: full PyTorch test accuracy uses 10,000 images, ONNX accuracy uses 2,000 images. A distillation gain is reported only if observed; it is not guaranteed.

Architecture implementations: [torchvision](https://github.com/pytorch/vision), [timm](https://github.com/huggingface/pytorch-image-models). Data: [CIFAR](https://www.cs.toronto.edu/~kriz/cifar.html). NAS: [Optuna](https://optuna.org/). Deployment: [ONNX Runtime](https://onnxruntime.ai/).
